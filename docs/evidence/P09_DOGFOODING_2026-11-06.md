# P09: dogfooding rerun on the seven projects

Master plan, P09 preamble: the dogfooding journeys it affects are run again. Method, authorization and projects: `P08_G11_DOGFOODING_2026-10-11.md`. The same pinned commits were used, confirmed against `scripts/dogfood/projects.json`.

**Status: run, with one check failed on one project.** Journeys B and E pass on all seven projects. Journey F failed one check on sb-admin-2, intermittently (#377).

- **Ninerr commit:** `e4e201f`, which is main `752491c` with this driver. All seven results record a clean tree. This record itself is on a later commit.
- **Machine:** Windows 11, 13th Gen Intel i5-13420H, 12 cores, 16 GiB, Node 24.19.0, Microsoft Edge. One run per project, one after another. No macOS or Linux run.
- **What it drives:** the editor from source, against a studio host started as `npm start` starts it, not an installed application. That is P10's work.

## What changed in the journeys
- **B:** reorder with Alt+Up, move into and out of a layer with Alt+Right and Alt+Left, drag past a sibling in the layers tree, group with Ctrl+G, set classes in the inspector, each undone or checked against the document and the canvas.
- **E:** the agent's change is offered as Undo agent change, named, next to Undo, and is undone there.

## What this does and does not show for P09
- **Criterion 1 (agent undo):** exercised on all seven.
- **Criterion 2 (reorder, group, reparent):** Alt+Up, drag and Ctrl+G ran on all seven. **Alt+Right and Alt+Left ran on only two projects, taxonomy and bulletproof-react.** The others have no layer that holds layers just above the box. `tests/layer-structure.test.mjs` covers these on a fixture.
- **Criterion 3 (classes):** exercised on all seven.
- **Not covered here:** Group by mouse, a multi-layer group, touch or pen, and writing a class back to source. Keyboard-only multi-select is tested in `tests/editor-accessibility.test.mjs`.

## The failed check
sb-admin-2, journey F, "the editor raised no errors": `POST /api/selection` answered 409, and the browser logged it. Across 7 runs of this project it failed twice: the evidence run and one of two reruns. Four further runs with a temporary probe to capture the body all passed, so **the response body has not been seen**. The likely mechanism, a pending selection racing a close made outside the tab, is inferred from the code (#377). The check was not loosened.

## Findings
- **#377:** the intermittent 409 above.
- **#378:** Ctrl+Z after tabbing out of an inspector field is that field's text undo, recorded on all seven projects.

The driver no longer marks reorder and group "unsupported", and no longer raises the P08 finding about Undo after an agent's edit.
