## Observed: layout (E-FG-11, E-FG-12)

- **Hug, fill, fixed are exact flexbox arithmetic.** In a 400 px horizontal Auto Layout frame (padding 12, gap 8): a fixed 50 px child, a fill child and a hug text (47 px). The fill child got 263 px = 400 − 24 − 50 − 47 − 16. Widening the frame to 600 px gave the fill child 463 px and moved the hug text by 200 px.
- **An absolute child** in an Auto Layout frame keeps its own `x`, `y` and leaves the flow (3 children in flow).
- **Context errors are inconsistent.** `layoutSizingHorizontal = "FILL"` on a child of a frame without Auto Layout throws ("node must be an auto-layout frame or a child of an auto-layout frame"). `layoutGrow = 1` on the same child is accepted silently and stored.
- **Constraints:** a 50×50 child at (140, 140) with horizontal `MAX` and vertical `STRETCH`; the parent grows from 200 to 300 px. The child moved to x 240 (its right margin kept) and grew to 150 px high (both vertical margins kept).
- **Code view:** `getCSSAsync()` on an Auto Layout component returns `display: inline-flex`, `padding: 8px 16px`, `align-items: flex-start`. **Inferred:** Figma itself presents Auto Layout as CSS flex for code (E-FG-19).

## Observed: components (E-FG-13)

- **Instance child IDs are paths.** The instance is `1:11`; the child drawn from the main component's `1:10` has the ID `I1:11;1:10`. **Inferred:** an instance's inner layers have no stored identity of their own; their ID is derived from the instance and the definition node.
- **Overrides are per field.** Setting the instance's fill recorded the overridden fields `fills`, `width`, `height` on the instance. A text value set through a component property is a property value, not an override.
- **Main-component changes propagate except where overridden:** a new main padding reached the instance; the overridden fill did not.
- **Structure inside an instance is locked:** appending a layer ("Cannot move node. New parent is an instance or is inside of an instance") and removing one ("Removing this node is not allowed") both throw.
- **Reset** (`resetOverrides`) restored the fill and kept the property value ("Buy now").
- **Variants:** combining two components as variants made a `VARIANT` property (`state`: default, hover), and **renamed the existing property keys** (`label#1:0` became `label#1:2`). A variant swap kept the instance's property values.
- **Detach** returns a plain frame.

## Observed: variables (E-FG-14)

- **Type checks:** a colour value for a number variable is refused ("Mismatched variable resolved type").
- **Alias cycles are refused silently:** setting `x` to an alias of `y`, which aliases `x`, raised no error, and `x` kept its literal value.
- **Binding:** a fill bound through an alias resolves, and follows a change to the aliased variable.
- **Deleting a variable in use** succeeded with no warning. The alias pointing at it stayed (now dangling), and the bound fill kept the last resolved colour.
- **Modes are plan-gated:** a second mode was refused on this Starter plan ("Limited to 1 modes only"). Modes per collection are *documented* for paid plans (E-FG-02).

## Observed: atomicity, undo and concurrency (E-FG-15 to E-FG-17)

- **No atomicity.** A script whose third write threw left the first two layers, and a third empty text layer, in the file. One earlier script that failed on the mode limit left the collection it had created.
- **Undo steps are what the caller commits.** With `commitUndo()` after x and after y, one `triggerUndo()` removed y and the uncommitted z together; a second removed x. With no `commitUndo()` between them, one `triggerUndo()` reverted five separate console scripts at once. *Documented:* "By default, plugin actions are not committed to undo history" (the `commitUndo` page).
- **A stale write from a second client wins, per property, with no precondition.** Client B read `itemSpacing` 8; client A set `itemSpacing` 20 and `paddingLeft` 30, which B had received before it wrote; B then wrote `itemSpacing` 9 from its old read and a new name. After a 3 s wait both clients showed `itemSpacing` 9, `paddingLeft` 30 and B's name. A's spacing was lost without either client being told. This was a sequential stale write, not a simultaneous one; it matches the *documented* per-property model (E-FG-01).

## Observed: Figma's built-in agent (E-FG-18)

- **The request:** a pricing card next to the existing layers that reuses the existing Button component, with Auto Layout and any existing variables.
- **Visible progress:** the agent listed its steps ("Inspect existing layers", "Create Pro pricing card", …) and worked for 1 min 46 s.
- **The result** reused the component: a vertical Auto Layout frame (fixed width, hug height) holding a nested frame, three texts, and an **instance** of Button with fill width. No variable existed to reuse.
- **Undo of an agent turn:** each reply has an Undo button. After the agent's turn, a person changed the price text inside the card and renamed another layer. The reply's Undo removed the whole card, the person's later edit inside it included, and kept the unrelated rename. No warning about the lost edit was seen.

## Documented: the agent interface (E-FG-03 to E-FG-08)

- **Servers (E-FG-03):** remote `https://mcp.figma.com/mcp`; a desktop server at `http://127.0.0.1:3845/mcp`.
- **Writing to the canvas (E-FG-05), read in full:**
  - "Professional, Education, Organization, and Enterprise plans"; edit access; the remote server. In beta, "free to use during the beta period", later "a usage-based paid feature".
  - `use_figma` runs Plugin API code. The page states no atomicity or undo for these writes. It advises: "test on a duplicate of your library or a draft file before changing production files, and keep a backup copy", and "make large changes in steps".
  - Limits: 20 KB of output per tool call; `use_figma` "can't add new images on its own"; fonts must be uploaded to the account; "Output is beta quality and may need manual review and cleanup".
- **Tools (E-FG-04):** about 32, read and write, including `get_design_context`, `get_metadata`, `get_screenshot`, `get_variable_defs`, `search_design_system`, `use_figma`, `generate_figma_design`.

- **Sync (E-FG-01):** Figma's engineering post on multiplayer: per-property last-writer-wins ordered by the server, fractional child order, client-generated IDs, per-client undo.

## What this means for Ninerr

The comparison with Ninerr, case by case and with evidence on both sides, is in [COMPARISON](COMPARISON_2026-10-18.md). For the plan:
- **Layout (ADR-0002):** Figma's own sizing is flex arithmetic, and Figma itself renders Auto Layout as CSS flex for code. Mapping hug, fill and fixed onto CSS needs no second layout engine.
- **Context-dependent properties:** Figma is inconsistent (one throws, one is stored). Ninerr's write report should name every property that has no effect where it is set (T11.5).
- **Instances (ADR-0005):** path IDs, per-field overrides, locked structure and reset that keeps property values are a tested shape to follow. Stable property IDs matter: Figma's are renamed when variants are combined.
- **Tokens (ADR-0004):** refuse cycles *with an error*, and refuse or report deleting a token in use instead of leaving dangling aliases.
- **Agent safety (ADR-0006):** the Plugin API takes no precondition (E-FG-17); whether the built-in agent checks what it read is unknown. A revert that discards a later edit should say so before it does (E-FG-18).
