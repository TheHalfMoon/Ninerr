# Design-platform reverse-engineering study, 2026-10-18

This is a study of three visual design products: Figma, Paper Desktop (paper.design) and Claude Design (Anthropic Labs). It was made to plan Ninerr's next phases as a visual design editor.

- **Records:** these dated files record what was observed, documented or inferred on 2026-10-18.
- **Plan:** the plan built from them is in [`docs/design-platform/`](../../design-platform/README.md).
- **Approval:** the plan is a **proposal**. It has no founder approval, and it does not change the approved P09 and P10 criteria or the release gate in `docs/MASTER_PLAN.md`.
- **Nothing copied:** no code, asset, file format or design of the studied products enters Ninerr. Ninerr's own history matters here:
  - Paper.design was once named as a donor (`docs/DONORS.md`).
  - Its shipped-package recovery study was retired in N0-G5.
  - Since then Ninerr has depended on no donor product or identity.
  - This study is a competitor study, and it keeps that rule.

## Evidence levels

Every finding carries one of these levels, and its evidence ID:

- **Observed:** seen directly in a controlled experiment run on 2026-10-18, through a supported interface, with the request and response recorded.
- **Documented:** stated in the vendor's own official documentation or engineering publication, retrieved on 2026-10-18.
- **Secondary:** stated only in third-party coverage. It is used for context, never as a basis for the plan.
- **Inferred:** a reasoned conclusion from observed or documented facts, stated as an inference.
- **Unknown:** not determinable with the access available. It is never filled in.

## Method and boundaries

**REA tooling.** REA (`morluto/rea`) is the npm package `rea-agents` 6.3.0. This is the copy already qualified on this machine, with npm integrity `sha512-1l3L22PY…ujkOfQ==`, the same as the earlier pin. REA was run from the local npx cache, with no new download. Its receipts are listed in [EVIDENCE](EVIDENCE_2026-10-18.md#rea-receipts).

- **`doctor`:** it reports no native analysis engines (Hopper, Ghidra, IDA), and its MCP registrations for other clients are stale. Neither was needed. `rea setup` was **not** run, because it would rewrite other clients' MCP configurations.
- **Not available on Windows:** REA's native-window observation (`capture-native-ui-scenario`, `observe-native-ui`) needs macOS. It reports `unsupported_host` on this Windows host. Black-box observation of Paper Desktop's window was therefore not possible, and Paper's own MCP server was used instead.
- **Browser provider:** used through a loopback CDP endpoint on an isolated, signed-out, headless Microsoft Edge 155 profile. Three commands ran on each product's public page:
  - `list-browser-targets`;
  - `discover-webmcp-tools`, which found no page-declared WebMCP tools on any of the three;
  - `inspect-web-page`, a passive capture of each public page.

**Interfaces used:**
- **Paper Desktop:** its official MCP server, the one the desktop app starts while a file is open, version as served on 2026-10-18. The experiments ran in a new file made for them ("Ninerr REA fixture 2026-10-18"). No other user file was opened or changed.
- **Figma:** the repository owner signed in to Figma in the Claude desktop app's browser pane. In a new draft file made for the study, experiments ran through the Plugin API that Figma documents in the developer console (the API its MCP write tool runs), and Figma's built-in agent was given one request. The developer documentation was read too.
- **Claude Design:** Anthropic's help center documents it as an artifact template usable in any chat and in Claude Code. The study made a private Design artifact from Claude Code and revised it; the canvas editor in the browser is covered in the record. The type's instruction file is not public and is not reproduced.
- **Ninerr:** the same cases, run by `scripts/research/ninerr-counterparts.mjs` against Ninerr's own host.

**Not done, by design:**
- no decompilation, bundle analysis, or debugger attachment to any proprietary application or web bundle;
- no paywall or access-control bypass; every account session used was signed in by its owner, and nothing was created in an account beyond the study's own fixture file or artifact;
- no copying of proprietary code or assets.

`analyze-web-bundle`, `analyze-javascript-application` and `capture-electron-scenario` were available, and deliberately not used on these products, because nothing authorizes analyzing their proprietary code.
